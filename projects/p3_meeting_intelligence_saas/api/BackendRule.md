# Backend Rules

Rules for every change in `api/`. A change is not done until it follows all of them.

## 1. Database optimization

- **Schema changes go through Alembic, never by hand.** Edit `db/models.py`, then
  `uv run alembic revision --autogenerate -m "..."`, review the file, and apply it with `.\run.ps1 -Migrate`.
  The app never creates tables itself (no `create_all()` outside tests).
- **Migrations must run on both MySQL and SQLite.** Use `op.batch_alter_table(...)` for column, constraint
  and index changes, give every constraint an explicit name, and use generic types (`sa.String`, not `mysql.VARCHAR`).
- **Migrations preserve data.** If a column is moved or dropped, copy its data in `upgrade()` and copy it back in `downgrade()`.
- **Every `String` column has a length** (MySQL can't create a `VARCHAR` without one).
- **Index every column used in a `WHERE`, `JOIN` or `ORDER BY`**, and give every `*_id` column a named
  foreign key with an explicit `ondelete`.
- **Lists are bounded:** endpoints that return lists are scoped to the caller and paginated (`limit`/`offset`, max 100).
- **No N+1 queries:** load related rows with `lazy="selectin"` or a join, not one query per row.
- **Files are recorded in the `uploads` table** (owner, category, path, type, size) via `UploadService`.
  Never store file paths or URLs on other tables.

## 2. Authentication & Authorization

- **Every endpoint requires `CurrentUserDep`** except: register, login, health, and static `/uploads`.
- **Users only access their own data:** filter queries by `current_user.id`. Return **404, not 403**, for
  another user's resource, so IDs can't be probed.
- **No endpoint lists all users or exposes other users' emails.** Admin-only features need a role check first.
- **Never return secrets:** response schemas exclude `hashed_password` and tokens; passwords are hashed with
  `core/security.py`.
- **`SECRET_KEY` must be set outside development/testing.** `config.py` refuses to start with the default key.

## 3. Error handling

- **Raise `AppException` (or a subclass in `core/exceptions.py`) for expected errors,** never a bare
  `HTTPException`, so every error response has one shape: `{"error", "message", "details"}`.
- **Use the right status code:** 400 bad input, 401 not logged in, 404 not found or not yours, 409 conflict,
  413 too large, 415 unsupported type, 422 validation.
- **Unexpected errors** are caught by the middleware in `main.py`: logged with a full traceback, returned as a
  generic 500 (with CORS headers). Never put internal details in a response.
- **Error messages are written for users** (the frontend shows `message` directly).

## 4. Security

- **Validate uploads by their contents, not by filename or `Content-Type`:** an allow-list of formats, a
  size limit read with `file.read(MAX + 1)`, and a pixel limit for images.
- **Re-encode user images** (removes EXIF/GPS and anything hidden). Never accept SVG or HTML uploads.
- **Storage paths are generated by the server** (`UploadService`); never build a path from user input.
- **CORS uses an explicit origin list** (`CORS_ORIGINS`), never `*` with credentials.
- **Secrets only come from `.env`** (git-ignored). Keep `.env.example` up to date with placeholder values.
- **Add rate limiting before production** on `/auth/login` and registration.

## 5. Performance

- **Never block the event loop:** endpoints that only do sync work (DB calls, Pillow, hashing) are plain `def`.
  In an `async def` endpoint, wrap sync calls with `await run_in_threadpool(...)`.
- **Bounded reads:** never `await file.read()` without a size limit on user uploads.
- **Heavy work** (transcription, LLM calls) must be truly async or run in a thread or worker, not inline sync code.
- **Database connections:** keep `pool_pre_ping` and `pool_recycle` for MySQL.

## 6. Testing

- **Tests never touch real data:** `tests/conftest.py` forces a temporary SQLite database and upload folder
  before the app is imported, and gives each test empty tables.
- **Every endpoint has tests for:** the success case, missing or invalid auth (401), another user's data
  (404), and validation failures.
- **Every migration is covered by `tests/test_migrations.py`** (upgrade to head, `alembic check` for drift,
  downgrade to base and back).
- **Run `.\run.ps1 -Test` (or `cd api; uv run pytest`) before finishing a change.** All tests must pass.
